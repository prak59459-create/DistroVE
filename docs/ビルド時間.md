# ビルド時間

計画の指示：**上限 60 秒・ねらい 10 秒**。

## 測り方

- GitHub Actions の macOS ランナー（Apple Silicon の仮想 Mac・3 コア）で、`scripts/ios-build.sh` が `DistroVE.swiftpm` を xcodebuild で iPadOS 向けにビルドして測ります。Swift Playgrounds と同じく Debug 構成・1 モジュールです。
- 3 つを測ります。
  1. **差分ビルド** … 1 ファイルだけ直してもう一度ビルド。ふだんの「直して ▶︎」に当たります。
  2. **クリーンビルド** … アプリのコードを全部作り直す。SDK（SwiftUI・AVFoundation など）のモジュールキャッシュはある状態。
  3. **初回ビルド** … SDK のモジュールキャッシュ作りから。その端末・その SDK で最初の 1 回だけかかります。
- `82a5b43` からは iPad と同じ **arm64 だけ**のビルド（`generic/platform=iOS`）で測ります。それより前はシミュレーター向けで、arm64 と x86_64 の 2 回分をコンパイルしていました。
- `scripts/ios-profile.sh` は全体を 1 プロセスでコンパイルし、コンパイラの段階（型チェック・SIL・LLVM）ごとの時間と、型チェックが重いファイルを出します。

## 結果（アプリ全体：62 ファイル・約 16,600 行、iPad と同じ arm64 だけ）

`aafe840` の CI（2026-11-19）の値です。

| 計測 | Xcode 16.4（Swift 6.1） | Xcode 26.6（Swift 6.3） | 判定 |
| --- | --- | --- | --- |
| 差分ビルド（1 ファイル変更） | 5 秒 | 6 秒 | ねらい 10 秒以内 ✅ |
| クリーンビルド | 28 秒 | 26 秒 | 上限 60 秒以内 ✅ |
| 初回ビルド（モジュールキャッシュ作成を含む） | 63 秒 | 65 秒 | 最初の 1 回だけ。上限を少し超える |

| 作業 | 時間 |
| --- | --- |

### それまでの計測（シミュレーター向け・2 CPU 分）

| 計測 | Xcode 16.4 | Xcode 26.6 |
| --- | --- | --- |
| 差分ビルド | 6 秒 | 6〜8 秒 |
| クリーンビルド | 32〜38 秒 | 34 秒 |
| 初回ビルド | 88〜97 秒 | 72〜74 秒 |

シミュレーター向けは arm64 と x86_64 の 2 回分をコンパイルするため、Swift のコンパイルが 64 秒（arm64 だけの約 2 倍）かかっていました。

### 型チェックの重い関数

CI は型チェックに 150 ミリ秒を超えた関数を警告で出します（`scripts/ios-typecheck.sh`）。見つかったものは直しました。

| 場所 | 直す前 | 直し方 |
| --- | --- | --- |
| 雑音の生成（`Synth.noise`） | 533 ms | 定数に型を付けて分けた |
| 書き出し画面の `body` | 239〜276 ms | 節ごとの計算プロパティに分けた |
| テンプレート画面の `body` | 236〜257 ms | 行を別の View に分けた |
| 設定画面の `body` | 173 ms | 節ごとに分けた |
| 色の 16 進変換 | 179 ms | 取り出しを関数にした |
| 動きの量の計算 | 158 ms | 式を分けた |
| タイムラインのクリップ描画 | 153〜301 ms | コマ・波形・名前・選択枠の描画を別の関数に分けた |
| フィルター画面の `body` | 202 ms | 選択肢を別の View に、格子と一覧を別の関数に分けた |

## iPad 実機について

実機では測っていません。Swift Playgrounds も前回のビルド結果を使い、変わったファイルだけを作り直します。ふだんの「直して ▶︎」は上の差分ビルドに当たり、最初に開いたときだけ初回ビルド（モジュールキャッシュ作り）の時間がかかります。

## 速く保つための決まり

- 型を書く（`let x: CGFloat = ...`）。リテラルと演算子が混ざる長い式は、途中の値に分ける。
- SwiftUI の `body` は小さく保つ。大きい画面は計算プロパティや別の View に分け、パネルの切り替えは `AnyView` で返す。
- マクロ（`@Observable`・`#Preview` など）は使わず、`ObservableObject` と `@Published` を使う（マクロの展開を省く）。
- 外部パッケージを使わない（取得と依存のビルドが要らない）。
- 演算子の多重定義を増やさない（`Time` の `+` と `-` だけ）。
- 新しく 150 ms を超える関数が CI に出たら直す。段階ごとの内訳は `scripts/ios-profile.sh` で見る。
