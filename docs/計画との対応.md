# 計画書との対応

計画書（Distro VE 計画書、2026-11-19）の項目（Q 番号）ごとに、実装した内容・状態・主なファイルをまとめます。
状態は ✅ 実装済み、🟡 一部（制約あり）、⏸ 未実装・利用者の判断待ち です。

## 第 2 章「先に決めたい点とリスク」の方針案

| 論点 | 採った方針 | 状態 |
| --- | --- | --- |
| 予算と公開 | 予算 0 円で作れる構成にした（外部の有料サービスなし、CI は公開リポジトリの無料枠）。App Store への提出は開発者アカウント加入後に Swift Playgrounds から行う | ⏸ 公開時期・年会費は利用者の判断 |
| GitHub 経由の更新 | App Store 版は通常の更新のみ。GitHub から受け取るのはテンプレート・LUT のデータだけ（`content/`、ハッシュ確認・次回起動で反映）。Swift Playgrounds 版のプログラムの差分更新は「アプリ内では不可」と判断（下の「試作で確かめたこと」） | ✅ データ更新 / 🟡 プログラムの更新は不可 |
| 動画処理の仕組み | AVFoundation・Core Image（Metal）・VideoToolbox で実装。FFmpeg は Swift Playgrounds に組み込めない（下の「試作で確かめたこと」）ため、FFmpeg が受け持つ部分（入れ物の読み取りと、端末に無い解読器）を Swift で書いた | ✅ |
| 言語と作り方 | Swift + SwiftUI（タイムラインは UIKit）。Web 技術は使わない | ✅ |
| 読み込み形式 | 利用者の回答（Q6）に合わせ、FFmpeg 相当まで広げた。MKV・WebM・AVI・Ogg・FLV・MPEG-TS（AVCHD の .mts・.m2ts を含む）は、取り込むときに端末の中で MP4（音声だけなら M4A）に変える（下の「FFmpeg 相当の取り込み」） | ✅（読めない中身は名前を出して知らせる） |
| プライバシー | 動画本体は端末外に出さない。サーバーを使うのは、端末内で文字起こしできない端末で利用者が許可したときの音声だけ | ✅ |
| 作る量 | 利用者の回答（Q6）：「全機能（FFmpeg 相当を含む）を完成させてから公開する」。段階を分けて全部を実装した（下の「段階」） | ✅ 段階 1〜5 の機能を実装、段階 6 は実機確認が残る |

## FFmpeg 相当の取り込み（Q6・Q71）

FFmpeg（C 言語）は Swift Playgrounds のアプリに入れられません。Swift Playgrounds は C・C++・Objective-C のパッケージや、組み立て済みのバイナリ（XCFramework）を扱えないためです（Apple の公式文書には書かれておらず、開発者フォーラムの報告によります：[SPM Binary Packages + Swift Playgrounds on iPad](https://forums.swift.org/t/spm-binary-packages-swift-playgrounds-on-ipad/62916)、[Binary XCFrameworks on Swift Playgrounds 4?](https://developer.apple.com/forums/thread/698119)、[Object-C Packages（Swift Playgrounds）](https://developer.apple.com/forums/thread/727514)、[Adding packages in Swift Playgrounds 4](https://forums.swift.org/t/adding-packages-in-swift-playgrounds-4/54173)）。

そこで、FFmpeg が受け持つ部分を Swift で書きました。取り込むときに、入れ物を Swift で読み、映像・音声を解読して、iPad の標準の形（MP4・M4A）に書き直します。

| 部分 | 対応 | 解読のしかた |
| --- | --- | --- |
| 入れ物 | MKV・MKA・WebM（EBML）、AVI（OpenDML を含む）、Ogg（.ogg・.oga・.opus・.ogv）、FLV（拡張 RTMP を含む）、MPEG-TS・M2TS（AVCHD の .mts・.m2ts） | Swift で読む（`Core/Formats/`） |
| 映像 | H.264・HEVC・MPEG-4（Xvid・DivX）・Motion JPEG | 端末の VideoToolbox・ImageIO |
| | VP8 | **Swift で書いた解読器**（RFC 6386 の参照実装を移植。ffmpeg の出力と 1 バイトも違わないことを確かめた） |
| | VP9・AV1・MPEG-2 | VideoToolbox（Mac では読めることを確かめた。iPad は端末によって読めない） |
| 音声 | AAC・MP3・MP2・AC-3・E-AC-3・FLAC・PCM・Opus | 端末の AudioToolbox（FLAC の全体のサンプル数が書かれていないときは、数えて書き直す） |
| | Vorbis | **Swift で書いた解読器**（仕様どおり。libvorbis の出力と SN 比 137dB で一致） |
| 字幕 | 入れ物の中の SRT・ASS | 文字として読み込み、クリップの位置に合わせる |

読めないもの（名前を出して知らせ、ほかに読めるトラックがあればそれを使います）：

- 入れ物：WMV・ASF、RealMedia（.rm・.rmvb）、MPEG-PS（.mpg・.vob）
- 中身：Theora、Sorenson Spark・VP6（Flash）、DTS、Blu-ray の LPCM、AAC の LATM、Speex、Nellymoser
- 長い動画は変換に時間がかかります。VP8 は Swift で解読するため、開発用の Linux（最適化ありのビルド）で 320x240 が毎秒約 260 コマでした。1080p に直すと毎秒約 10 コマの見込みで、最適化なし（Debug）のビルドでは 10 倍ほど遅くなります。iPad では測っていません

## 試作で確かめたこと（第 9 章の「最初にやること」2）

- **外部ライブラリ**: 使わずに全機能を作れた（AVFoundation・Core Image・Vision・Speech・Accelerate など Apple 標準のみ）。Swift Playgrounds では外部パッケージを URL で追加できるが、`Package.swift` はアプリの設定を変えると作り直されるため、手で足したものが消える恐れがある。外部ライブラリを使わない構成にした。
- **GPU 処理**: 合成・色・エフェクトは Core Image を Metal で動かしている。macOS の CI で書き出しテストが GPU で通ることを確認（`FrameRenderer.usesGPU`）。
- **GitHub からの差分更新（再起動で反映）**: データ（テンプレート・LUT）は実装済み。プログラムは、Swift Playgrounds が作ったアプリが自分のソースを書き換えて作り直す仕組みが無いため、アプリ内からは更新できない。新しい `DistroVE.swiftpm` を取り込み直す運用にする。
- **FFmpeg**: Swift Playgrounds には C のライブラリもバイナリも入れられない（上の「FFmpeg 相当の取り込み」）。入れ物の読み手と、端末に無い解読器（VP8・Vorbis）を Swift で書いた。VP8 の部分は RFC 6386 の参照用の解読器（BSD ライセンス、Google Inc.）を移植したもので、著作権表示を `Core/Formats/VP8Tables.swift` に残している。
